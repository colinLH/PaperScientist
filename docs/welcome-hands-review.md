# Welcome 星云与手势交互审查（2026-10-24）

## 审查结论

接手时有 `hand-motion.mjs` 的粒子采样、张合度、双手槽位与淡出辅助逻辑，
以及对应的纯数学测试；页面没有导入它，也没有摄像头请求、MediaPipe 模型、
检测 Worker、手部粒子渲染或摄像头预览。因此原版是算法准备阶段，尚未完成运行时功能。

## 预算与实现边界

- 沿用单个 Three.js WebGLRenderer；粒子作为第二个轻量绘制层，最多多一个 draw call。
- 镜头移动与其他章节缓冲区上限 140 万像素、DPR 上限 1.25；第四幕停稳后按屏幕像素提高到最高 829 万像素、DPR 上限 2。粒子数量按设备选一次，Resize 不重新分配。
- 模型仅在摄像头可用且抵达第四幕时加载；检测与 UI 分线程，按推理耗时调整间隔。
- 相机帧、关键点只在浏览器内使用，不发送到服务端。依赖及模型全部同源加载。
- 手形由关键点估计轮廓，不是像素级皮肤分割；双手长时间完全遮挡、交叉重叠仍可能影响识别。
- 手部粒子沿用深度坐标，正交投影到画面并按深度略调点径；不影响原场景摄像机路径。
- 低配置设备仍受实际 CPU、摄像头曝光与模型推理速度限制；没有以桌面样例测试代替低端真机流畅度验收。

## 验证记录

1. 25 项 Node 回归测试：配乐、滚轮反向、粒子采样与预算、淡出、手部槽位、摄像头拒绝/重试、迟到授权、帧背压、Worker 失败与释放、光轨闭合及 Resize。
2. Python 开场路由测试：页面/深链接、音频 Range、WASM MIME 与 Range、Worker 静态路径。
3. 浏览器实际查看第四幕与观测站；星图连续、圆环无原来的阶梯状碎边；未见 WebGL 着色器错误。
4. 使用 Google 官方示例照片，经 Canvas 视频轨道输入**真实 MediaPipe Worker**，实际识别出两只手、渲染 3000 粒子；切换空画面为 0 手/0 可见粒子，再返回为 2 手/3000 粒子。
5. 渲染视口从桌面缩至 390×700 后，分配数仍为 3000；销毁后视频轨道为 `ended`，WebGL 画布数为 0。
6. 当前自动化浏览器报告 `NotFoundError`（没有可用摄像头），已验证页面展示“未找到摄像头”和重试入口。**真人摄像头移动、握拳与弱光识别仍需在有摄像头的浏览器确认**。张合映射已通过算法测试；官方照片测试不等同真人动作测试。

本地验证证据在 `.test-output/intro-upgrade/`，不打包进产品页面。
测试页面显式标记为预录官方样例，没有把模拟输入伪装成摄像头测试。

## 4K 清晰度更新

- 背景由原先的 1024×503 素材改为 3840×2160 WebP（2,534,032 字节）。按用户选择，先参考原构图生成 1672×941 的蓝色星云，再用本地 Real-ESRGAN x4plus 超分和 Lanczos 导出；这是超分艺术素材，不是原生 4K 天文观测照片。
- 第四幕停稳后提高绘制分辨率，切换镜头时恢复原预算；第四幕不再叠加颗粒、薄雾和雾精灵。流星与星星闪烁着色器保持原样。
- 离线增强模型不随页面加载。生产页面只读取一张 4K 纹理，原参考图和生成源图保留作构建来源。
- 修复 Windows 文件关联把 WebP 标为 text/plain 的问题，固定返回 image/webp。
- 本次 27 项 Node 测试、2 项 Python 路由/MIME 测试通过；HTTP 实际读取的纹理尺寸、SHA-256 和 MIME 正确。确认没有运行中的研究任务后重启服务，6 个会话仍可读取。
- 本次浏览器控制连接中断，未完成更新后的整页截图与 4K 真机帧率复测；上方浏览器记录属于此前的手势/光轨版本，不作为本次 4K 视觉验收。素材全图及局部对比已直接检查。

素材来源、精确生成提示词、增强命令和哈希见 `paperscientist/static/intro/textures/`；本次验证记录在 `.test-output/nebula-hd/verification.json`。
