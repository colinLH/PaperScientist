# Change delivery and daily record

After a requested theme is implemented, inspect the diff, run relevant checks, make a descriptive commit and push it. Verify the remote commit before marking delivery complete. Never publish local credentials, session databases, execution workspaces or unrelated changes. If local history diverges, prepare a clean worktree from the current remote; do not rewrite the development checkout or force-push.

Keep a dated record under `docs/changes/` with the user-visible behavior, relevant checks and remaining limits. Group related changes rather than enumerating every line edit. Record commit links in the Feishu copy after their hashes exist.

The daily destination is https://my.feishu.cn/wiki/Ea6lwgDPBi0jLSkbLJfc6pf7nCe. Use Asia/Shanghai dates, one date heading per day, and a separate paragraph/subheading with a separator for each theme. Read before writing, append under the existing date where present, and verify by reading back. Compare commit hashes to avoid duplicate entries. A local draft or an authentication error is not a successful sync.

The daily follow-up may synchronize already reviewed/pushed changes. It does not authorize arbitrary commits, force pushes, publication of private research artifacts or edits to unrelated Feishu content. When there are no new changes, remain quiet.
