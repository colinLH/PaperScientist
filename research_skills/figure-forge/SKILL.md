# Paper figure production — first choice

Start with a drawing brief. State the one thing the reader should learn, the source of that claim, the final width in the manuscript and the visual comparison or mechanism that will explain it. Search `search_figure_references` with the topic and a layout pattern. Inspect a relevant reference or two and carry over a design decision (reading order, grouping or scale). Build the scientific content from the current paper. The pinned [Top-Conf Figure Gallery](https://github.com/qwdwqfwq/topconf-paper-figure-gallery) supplies references for this step.

Write the spec with `write_file`, then call `figure_forge(spec_path, brief)`. Read [the specification](specification.md) for working examples. Choose the kind according to the content:

- Use `results` for measured values. Show ordered trends as lines, relationships as scatter, distributions of raw repetitions as boxes, and estimates with supplied uncertainty as interval plots. Horizontal intervals leave room for long method names. Label the units, the sample and the meaning of uncertainty. Keep series identities and scales comparable across panels. The tool exports the source CSV, spec, standalone plotting code, editable SVG, PDF and 300-DPI PNG.
- When comparable metrics share a unit and a useful direction, use a CSV-backed `radar_grid` for paired profiles across two declared facets. Preserve planned conditions, missing cells and per-axis denominators.
- For a paper's method or architecture overview, start with `type: "framework", layout: "mechanism"`. Sketch the main path across the page at its intended width. Within each stage show what changes: a field is extracted, a representation acquires a dependency, a predicate selects a branch, or a tool receives an argument. Carry the same variable name or small source mark across stages. Put the condition directly beside its outgoing paths. A compact symbol beside a label can identify an actor. Use the main panel area for operations, local graphs and data structures supported by the method. Leave enough room to follow each connection.
- Use the coordinate-based `framework` layout when the paper needs bespoke routing or precise node positions. Use `framework_plate` for panels whose appearance itself conveys evidence, such as a specimen, scene or instrument view. An image model can supply a small visual detail; set exact technical fields and arrows as vectors. Both figure types preserve their editable source.
- Use `illustration` for a conceptual image, such as how a sensor probes a sample or how an approval boundary separates untrusted input from a tool. Describe the mechanism in a short self-contained prompt, supply only the concepts required, give the reading order, and specify any exact labels and arrow directions. Pick one visual focus and request space around it at the final aspect ratio. The configured MicuAPI image service receives the prompt. The artifact bundle retains the generated pixels, a PDF, the spec and the provider/model provenance.

Inspect the actual render. For a method figure, trace one concrete input to its final state at the manuscript width. Hide decorative symbols mentally and check that the operands, branch condition and outcome still read. Examine the smallest cell and every junction at final size. Check that every named entity, label and directed relationship agrees with the brief. Compare numerical marks with their source rows. Review type size, overlaps and contrast at the manuscript width, including in grayscale. Correct the specific discrepancy in the spec and render again. Preserve a draft with unresolved defects as a draft. If the active model cannot inspect images, give the preview to the configured vision reviewer or the user and record the pending review.

This approach adapts the reference, planning and critique stages in [PaperBanana](https://proceedings.mlr.press/v306/zhu26ag.html), discussed in the [Xinfinite walkthrough](https://www.xinfinite.net/t/topic/17381). Use visual hierarchy for explanations and legible, editable marks for evidence as described in [Nature's conceptual illustration guide](https://www.nature.com/documents/Nature_scientific_illustration_author_guide.pdf) and [figure specifications](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/). Combine hue with shape, pattern or direct labels as in [Wilke's redundant coding examples](https://clauswilke.com/dataviz/redundant-coding.html).

Declare sample size and its unit (cases, devices, independent seeds, etc.). Controlled fault-grid cases are not IID repetitions. Aggregation is explicit; missing cells are not implicitly zero. Preserve unsuccessful cases. A measured result requires registered experimental provenance; unregistered/synthetic sources are visibly labelled and cannot substantiate a scientific claim.

Before rendering for a manuscript, persist its layout with `configure_manuscript_layout`. Copy the user's single/double-column choice exactly; when no choice exists, record the existing portrait layout as inferred. Add `"manuscript": "manuscripts/draft/main.tex"` and `"figure_scope": "column"` to the figure spec. The renderer binds the target width to that contract. `page` scope is allowed in a double-column document only when spanning figures were explicitly authorized. Design at the final physical width; split/reflow dense panels instead of drawing wide and shrinking. Never introduce landscape pages, sideways figures or full-width floats to avoid a layout failure.

After inclusion call `compile_latex`, then `validate_manuscript_layout`. Only an instrumented compile plus actual PDF geometry, object bounds and effective vector-font checks can pass. Source regex checks, a compiler exit code, or an attractive standalone wide figure are insufficient. Fix every blocking diagnostic and inspect the final rendered pages for overlaps; the automated gate does not claim scientific or complete visual review.

For a layout reference, compare the [GPT Image research-figure gallery](https://github.com/wuyoscar/GPT-Image2-Skill/blob/main/skills/gpt-image/references/gallery-research-paper-figures.md), the modular asset and exported-preview workflow in [research-figure-pipeline](https://github.com/FuJincheng-01/research-figure-pipeline/blob/main/skills/research-figure-pipeline/SKILL.md), and the retrieval, planning and critique stages of [PaperVizAgent](https://github.com/google-research/papervizagent). Use the configured provider and render measured marks from local data.
